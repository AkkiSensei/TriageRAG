# ADR 0013: Evaluation Rebuild, Statistical Validity Self-Tests, and Benchmark Governance

## Context
Prior to AUB Phase 4, TriageRAG's evaluation suite suffered from severe structural and methodological validity issues identified in **AUB-EVL-01** and **AUB-ABS-02**:
1. **Data Leakage in Splits**: Benchmark splits were generated by randomly shuffling rows across near-duplicate synthetic scenarios. 224 cases shared only 20 distinct target label sets, allowing clinical scenario templates to leak across train/dev/test partitions.
2. **Reviewer B's Challenge Question**: The system lacked position-prior baselines (e.g. predicting the most frequent grade-2 node per syndrome). The evaluation could not answer whether Recall@1 was anything more than memorizing label frequencies.
3. **Metric Conflation and Artificial Calibration**: `wrong_protocol_rate` conflated false acceptances on distractors with clinical misrouting. Expected Calibration Error (ECE) was calculated using a hardcoded artificial confidence of 0.95 rather than genuine model retrieval confidence scores.
4. **Permissive Passing Gates**: Benchmark acceptance ignored candidate pool size and unrouted vitals-only cases. A trivial or constant retriever could not fail the gate explicitly on validity grounds.
5. **Human Annotation Governance**: Labels authored during initial synthesis carried `AGENT_AUTHORED_UNREVIEWED`. The repository lacked blinded annotation extraction, annotation schema validation, inter-annotator agreement tooling (Cohen's $\kappa$), and an honest ledger of ground truth provenance.

## Decision

1. **Template-Grouped Dataset Splits with Cryptographic Hash Lock (T4.1 / AUB-EVL-01)**:
   - Implemented `derive_template_id()` and `stratified_template_group_split()` in `eval/retrieval/build_dataset.py`.
   - Partitioned all 224 cases strictly by clinical template ID across 55 groups (42 dev groups with 143 cases; 13 test groups with 81 cases).
   - Generated `eval/retrieval/dataset.lock` and `eval/retrieval/split_manifest.json` recording SHA-256 hashes of dataset and corpus, seed 42, group counts, zero template group leakage, and zero target node-set leakage between dev and test.

2. **Blinded Annotation Protocol & Inter-Annotator Agreement Tooling (T4.2 / AUB-EVL-01)**:
   - Authored `docs/evaluation/ANNOTATION_GUIDE.md` establishing a formal 3-level relevance grading rubric (Grade 2 = Directly Actionable, Grade 1 = Supporting Context, Grade 0 = Irrelevant or Contraindicated).
   - Created JSON schema `eval/annotations/schema.json` and export/agreement CLI `tools/export_annotations.py`.
   - Exported 100 blinded candidate cases (`eval/annotations/blinded_cases.json`) stripping ground truth labels, notes, and reviewers.
   - Authored `eval/annotations/agreement_status.json` recording honest status: `BLOCKED_PENDING_INDEPENDENT_HUMAN_ANNOTATION`. No artificial or fabricated Cohen's $\kappa$ is claimed before independent clinical dual-annotation occurs.

3. **Random and Position-Prior Baselines (T4.3 / Reviewer B's Challenge Question)**:
   - Implemented `PositionPriorRetriever` in `eval/run_retrieval.py` strictly fitted on the development split (never inspecting test split labels), with deterministic alphabetical tie-breaking.
   - Evaluated paired difference bootstrap 95% confidence intervals against the position prior.
   - Decisively answered Reviewer B's challenge question: Production BM25 test Recall@1 (54.00%) significantly outperforms the label frequency prior (24.00%) with a +30.00 pt advantage (95% bootstrap CI `[12.0, 48.0]`), confirming that system retrieval genuinely captures patient-specific signals beyond label distribution priors.

4. **Honest Metrics and Granular Abstention Diagnostics (T4.4 / AUB-ABS-02)**:
   - Disentangled `wrong_protocol_rate` into `false_accept_rate` (FAR = unindicated retrievals / expected abstentions) and `wrong_syndrome_rate` (WSR = discordant syndrome retrievals / positive retrievals), retaining legacy WPR for backwards compatibility.
   - Replaced static confidence with genuine normalized retrieval scores for honest ECE reporting.
   - Extended evaluation to Recall@{1, 3, 5, 10}, MRR, and graded nDCG@{5, 10}.
   - Added `per_code_abstention` reporting precision, recall, and support per `AbstainCode` enum.
   - Implemented cluster-robust group (template-level) bootstrap resampling for 95% confidence intervals.

5. **Benchmark Validity Self-Tests and Strict Acceptance Gates (T4.5 / AUB-EVL-01)**:
   - Implemented `validate_benchmark_gate()` enforcing two automated validity self-tests:
     1. Random baseline Recall@5 must be $< 60.0\%$ (verifying non-trivial candidate pool size).
     2. Position-prior Recall@1 must be lower than system Recall@1 with paired difference CI strictly excluding zero.
   - If either self-test fails, the benchmark collection is declared `BENCHMARK_INVALID`.
   - Enforced hard production gates: `false_accept_rate == 0.0`, `wrong_syndrome_rate == 0.0`, `wrong_protocol_rate == 0.0`, `abstain_recall_hard_negatives == 1.0`, syndrome-provided Recall@5 $\ge 95.0\%$, and bit-for-bit determinism.

6. **Hand-Computed Metric Verification Fixtures (T4.6)**:
   - Authored `docs/evaluation/METRICS.md` with full mathematical definitions, denominators, edge cases, and clinical safety rationale.
   - Authored `tests/unit/test_aub_phase4_metric_fixtures.py` verifying Recall@{1,3,5,10}, MRR, nDCG@{5,10}, FAR, WSR, legacy WPR, per-code abstention, Cohen's $\kappa$, and ECE against pencil-and-paper hand calculations.

7. **7-Arm Retrieval Ablation and Deterministic Backend Selection (T4.7)**:
   - Implemented all seven controlled retrieval configurations in `eval/run_retrieval_ablation.py`:
     1. `bm25` (Production BM25: Lexical + Calibrated Predicates)
     2. `bm25_pure_lexical` (Pure Lexical BM25: No Predicates, No Contextual Chunking)
     3. `char_ngram` (Character Trigram TF-IDF Cosine Vector Retriever)
     4. `hybrid_rrf` (Hybrid Reciprocal Rank Fusion: BM25 + CharNgram)
     5. `hybrid_rrf_rerank` (Hybrid RRF + Lexical Overlap Reranker)
     6. `bm25_contextual` (Contextual BM25: Contextual Chunking Headers, No Predicates)
     7. `contextual_predicate` (Contextual + Predicate BM25: Both Experimental Features)
   - Computed paired difference 95% bootstrap CIs vs baseline BM25 across 1,000 resamples.
   - Codified `decide_backend()`: requires non-regressing Recall@5, test MRR gain $\ge +0.05$, and paired difference 95% bootstrap CI strictly excluding zero.
   - Results: Predicate scoring improves over pure lexical BM25 by +0.0800 MRR (95% CI `[+0.0267, +0.1500]`, strictly positive) and eliminates false accepts on ambiguous vitals (FAR drops from 0.1935 to 0.0000). Contextual chunking on top of predicates achieves +0.0533 MRR point estimate, but its 95% CI `[-0.0067, +0.1200]` crosses zero at the 95% confidence level. In accordance with strict statistical standards, `bm25` (with calibrated predicates) is retained as the default production backend.
